# ${PROJECT_NAME}

Generated by `mise run kaggle-init ${SLUG}`.

This repository is a Kaggle-ready scaffold with GPU-aware dependencies, sensible defaults, and task scripts to accelerate exploration and baseline model building.

## Requirements

- Python >= ${PY_VERSION} (managed by uv)
- uv (https://docs.astral.sh/uv/)
- Kaggle credentials (either environment variables or `~/.kaggle/kaggle.json` with permission 0600)
- Optional: direnv (recommended for auto-activation of `.venv` and `.env`)

## Quickstart

- Initialize dependencies and environment:
  - Inside the project directory: `uv sync`
  - Optional: `direnv allow` to enable auto-activation
- Download data for the competition:
  - `mise run kaggle-download ${SLUG}`
- Start the marimo notebook editor:
  - `mise run nb-serve`
- Run the baseline training script:
  - `mise run train`

## Project layout

- `configs/`
  - `config.yaml` — experiment configuration (device, task, metrics, xgboost params, paths)
  - `logging.yaml` — Python logging configuration
- `data/`
  - `raw/` — raw competition files (unzipped)
  - `interim/`, `processed/`, `external/` — pipeline stages
- `notebooks/`
  - `eda.py` — marimo-based EDA notebook (theme: ${THEME})
  - `train.py` — quick XGBoost training notebook
- `src/`
  - `__init__.py` — package init
  - `paths.py` — common project paths
  - `data.py` — data utilities (download, unzip, validation)
  - `features.py` — placeholder feature functions
  - `models.py` — baseline models (XGBoost and PyTorch)
  - `viz.py` — simple visualization helpers
- `runs/` — training outputs (models, metrics)
- `logs/` — logs for tasks and pipelines
- `.env.example` — copy to `.env` to set local secrets
- `.envrc` — direnv config to auto-activate `.venv` and load `.env`
- `pyproject.toml` — project metadata and dependencies

## Tasks (via mise)

- `mise run kaggle-download <slug>`
  - Downloads competition archives into `data/raw` and extracts to `data/raw/<slug>`
  - Options: `--force`, `--keep-zip`, `--project <dir>`
- `mise run kaggle-submit --file submission.csv --message "My submission"`
  - Validates and submits a file to Kaggle
  - Options: `--slug <slug>`, `--project <dir>`
- `mise run nb-serve`
  - Launches marimo on `notebooks/eda.py`
  - Env: `MiseMarimoPort` (default: 2718)
- `mise run train`
  - Runs the baseline training module `src.models` with uv

## Kaggle authentication

Use one of the following:

- Environment variables (preferred when both exist):
  - `KAGGLE_USERNAME`, `KAGGLE_KEY`
  - Copy `.env.example` to `.env` and fill values, or export in your shell
- `~/.kaggle/kaggle.json` with permission `0600`

The scripts will attempt to fix permissions for `kaggle.json` automatically.

## GPU notes

- Device is auto-detected (CUDA > ROCm > CPU) unless overridden via config.
- Torch installation:
  - CUDA: uses appropriate index (e.g., cu121) when possible
  - ROCm: uses ROCm wheels
  - Falls back to CPU if GPU wheels are unavailable
- You can force device selection in `configs/config.yaml` via `device: cpu|cuda|rocm|auto`.

## Common commands

- Pin and sync Python/deps: `uv python pin ${PY_VERSION} && uv sync`
- Add packages: `uv add <package>`
- Run Python module: `uv run -- python -m src.models`

## Troubleshooting

- If downloads fail, verify Kaggle credentials and network access.
- If GPU install fails, training will automatically use CPU.
- Check `logs/` for detailed logs; initialization logs are timestamped.
